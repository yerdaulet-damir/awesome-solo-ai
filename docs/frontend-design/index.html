A curated guide to frontend libraries, animation tools, design inspiration and agent skills for distinctive landing pages, portfolios and product websites. Includes Motion (Framer Motion), GSAP, 21st.dev, React Bits, scroll-craft and scroll-world, with a reason to choose each.

Updated 16 October 2026. Links point to official sites, documentation or author repositories. Paid editors, generated assets and component licenses are separate costs; check the linked terms for your use.

Start with the page you need

An AI-generated website looks generic when its layout, images and claims could belong to any product. A font, gradient or component library is not the cause by itself. Start with the product's actual screenshots, photography, explanation and next action, then choose tools that support them.

What you are building A useful starting point What deserves the design work
Editorial site, portfolio or documentation Astro and CSS; add small interactive islands where needed Typography, image selection, reading order and navigation
Marketing site attached to a React product Next.js, a headless UI foundation and Motion for component transitions Real product states, responsive layouts and shared interactions
Scroll-driven product story GSAP ScrollTrigger; optionally Lenis A useful sequence, mobile composition and an accessible static version
Interactive 3D product demonstration Three.js or React Three Fiber Lighting, camera, model size and a lightweight fallback
Designer-managed marketing site Framer or Webflow A layout and CMS workflow the site owner can maintain
One immersive video-scroll experience scroll-craft or scroll-world Original scenes, continuous transitions and media loading on phones

Choose one route for the page. Adding every library below usually creates more integration work than visual quality.

Save references with a note such as “the product image explains the offer before the headline” or “this menu stays usable on a small screen.” Copying a whole site's visual identity is not a design brief.

Frameworks and visual website builders

These determine rendering and editing workflows. They do not supply a visual identity.

Resource Choose it when Consider before choosing
Astro · source Most of the site is content and only some regions need JavaScript. Plan which components need hydration; a mostly interactive application may suit another framework.
Next.js · source A React marketing site needs to share code or server features with the product. Choose static rendering, server rendering and client components deliberately; a brochure page does not need every app feature.
SvelteKit You want Svelte components, routing and a choice of rendering/deployment approaches. Check the adapter and hosting environment you will use.
Nuxt Your team or product already uses Vue and needs a site framework. Decide how each route is rendered and where interactive code is necessary.
Framer Designers need visual control over a marketing site and its publishing workflow. Hosted publishing, CMS, marketplace assets and plan limits have their own terms. Framer the site builder is distinct from Motion the animation library.
Webflow A site owner needs visual layout tools, CMS content and hosted publishing. Check the current plan, CMS requirements and any export or hosting constraints before committing the project.

Component libraries and registries

Start with accessible behavior for menus, dialogs and forms. Then use a registry or block library for a particular section. A component that looks good in its demo still needs your content, error states and responsive checks.

Resource What you get Where it fits
Radix Primitives · source Unstyled React primitives for interactive UI. Custom-styled dialogs, menus and controls where behavior matters more than a preset appearance.
Base UI · source Unstyled React components with composable APIs. An alternative foundation when you want to own styling and composition.
shadcn/ui · source Component source you bring into your project, plus a registry format. Owning and adapting your UI code. Inspect third-party registry code separately from the core project.
21st.dev · agent integration A component catalog and an MCP workflow for coding agents. Finding a specific React/shadcn component with a preview. Catalog access, installs and AI generation have different limits; check current pricing and the selected component's license.
React Bits · source Animated text, backgrounds and interactive visual components. One effect that serves the page. Its MIT + Commons Clause terms differ from plain MIT.
Magic UI · source Animated React/Tailwind components and visual patterns. An intentional accent or interaction; several unchanged demos together can make the page feel borrowed.
Aceternity UI React effects, components and marketing blocks. A section or interaction that matches the direction. Free components and paid blocks/templates have different access and terms.
Motion Primitives · source Small animated components built with Motion. Focused text, disclosure and transition patterns whose timing you can tune.
Tailark Marketing blocks and pages with registry installation. A starting structure for marketing content; inspect the selected kit because OSS and paid content are distinct.
HyperUI · source Copyable Tailwind markup for marketing, commerce and application UI. Simple sections you can reshape without adopting a component runtime.
Origin UI · source React/Tailwind components following shadcn conventions. Form and application patterns; a useful addition when the landing page includes an interactive product surface.
Park UI · source Styled component source built on Ark UI and Panda CSS. A coherent starting system when you prefer its styling approach.
Tailwind Plus Commercial UI blocks and templates from the Tailwind team. Conventional sections that save implementation time; review the commercial license before using or redistributing them.

Motion and scroll animation

Choose the smallest tool that expresses the interaction. A static page can be distinctive. Animation earns its cost when it explains a transition, responds to input or helps someone follow a sequence.

Resource Use it for Main tradeoff
CSS scroll-driven animations · examples Reading progress, simple view/scroll timelines and progressive enhancement. Check target-browser support and keep the non-animated page usable.
Motion, formerly Framer Motion · source React layout changes, enter/exit transitions, gestures and scroll-linked components. Use the React API where component state drives movement; simple CSS transitions need no library.
GSAP and ScrollTrigger · examples Timelines, pinned product stories and several elements synchronized to scroll. Own animation cleanup and responsive behavior. GSAP and its plugins are free under the current license, which is not an unrestricted MIT license. See Webflow's announcement.
Lenis Optional smooth scrolling and integration with scroll animation. Changes scrolling behavior; test keyboard input, nested scrollers, reduced motion and low-powered devices. Native scrolling is a valid default.
Anime.js · source Timelines and animation of DOM, SVG and JavaScript values. Check examples against the installed major version and implement reduced-motion behavior for your effects.
Rive Interactive vector illustrations with state machines and app-controlled inputs. The runtime, editor plan and animation asset have separate licensing and performance considerations.
Lottie Web · dotLottie Web Playing supplied motion assets and exported vector animations. Test the actual asset in the chosen player; export support and composition complexity affect fidelity and startup cost.

For a direct GSAP vs Motion comparison and a complete React example, use the frontend motion guide.

3D and interactive illustration

Use real 3D when the visitor needs to inspect or manipulate an object. For a pre-rendered camera journey, video scrubbing can be a different implementation choice; it does not make the scene interactive 3D.

Resource Use it for Plan for
Three.js · examples Custom 3D scenes, model viewers and rendering experiments. Model compression, texture sizes, lighting and a device-appropriate rendering budget.
React Three Fiber · source Three.js scenes expressed as React components. Three.js knowledge and a version compatible with your React application.
Drei · source Cameras, controls, loaders and other helpers for React Three Fiber. The dependencies and rendering behavior of the helpers you select.
Spline · web export docs Visually authored interactive scenes embedded in a website. Editor/export terms, scene weight and whether a static image is enough on mobile.

For an immersive scene chain generated by an agent, see scroll-world below. Keep the headline, navigation and primary action in HTML so they remain available while media loads.

Typography and icons

A display font is only one decision. Check the actual headline at phone width, the body text's reading size, language coverage and the font license. Use one icon family for ordinary controls so stroke weights and proportions stay consistent.

Frontend skills for Claude Code and Codex

Skills are instructions and supporting files an agent reads. They are different from component packages and animation runtimes. Read a skill's requirements and inspect its scripts before giving it access to a project.

Skill Author repository What it adds
frontend-design Anthropic's skill A workflow for choosing a visual direction and implementing an interface with attention to typography, layout and detail.
scroll-craft nateherkai/scroll-craft A workflow and supporting tools for scroll-driven websites, references, responsive composition and visual verification. Uses supplied assets or optional generated media; media generation can cost extra.
scroll-world oso95/scroll-world A continuous camera journey assembled from scene images and video clips, then scrubbed by scroll. Requires media tooling and may require paid generation services.
ui-ux-pro-max nextlevelbuilder/ui-ux-pro-max-skill Design references and guidance for interface styles, typography, palettes and implementation choices. Use the references to make a choice rather than generating a new palette for every section.

Follow each repository's installation instructions for your agent. In scroll-craft, keep the skill's references, scripts and engine together. In scroll-world, plan asset generation and mobile media before starting a long scene chain. Neither skill guarantees a usable result without reviewing the rendered page.

A practical workflow for a distinctive landing page

  1. Write the offer in plain words. Decide what a visitor needs to understand and which action the page should make possible. Gather actual product screens, photos or examples that support the claim.
  2. Pick a few references for different decisions. Record what you are borrowing from each: type hierarchy, image treatment, information order or an interaction. Use licensed assets you can publish.
  3. Choose a framework and a UI foundation. Bring in one component or animation at a time. Give an agent exact reference URLs and ask it to explain why each dependency is needed.
  4. Build a static first screen with the real headline, image and action. Check phone width before expanding the page. A font ban or a compulsory black-and-green palette is not a substitute for this check.
  5. Add movement where it helps explain something. Keep body content visible when scripts fail, provide reduced-motion behavior and make the mobile version work without hover.
  6. Test the rendered site. Use keyboard navigation, narrow viewports, slow-network loading and real links/forms. Review one full-page screenshot as well as the actual interaction.

Useful primary references: web.dev Learn Accessibility, MDN reduced-motion media query, Chrome Lighthouse and Playwright. Lighthouse is a technical check; a score does not judge composition or whether the offer is understandable.

Questions about AI slop and frontend libraries

Which libraries help make an AI-generated website less generic?

Use galleries to choose a direction, a UI foundation such as Radix, Base UI or shadcn/ui for behavior, and a focused resource such as 21st.dev, React Bits or Motion Primitives for a particular interaction. The distinguishing work is adapting the layout, imagery, copy and motion to the actual product. A registry cannot make that choice for you.

Should I use GSAP or Framer Motion?

Motion, formerly Framer Motion, is convenient for React component state, gestures, layout and enter/exit animation. GSAP is useful for coordinated timelines and scroll sequences. They overlap; use the one that matches the interaction and your project. A page does not need both by default.

Is GSAP free, including ScrollTrigger and SplitText?

Webflow's GSAP announcement makes GSAP and its plugins free, including commercial use. The current product terms still govern use; do not describe it as MIT or repeat the old blanket claim that SplitText requires a Club GSAP subscription.

Is a scroll-world site the same as a Three.js website?

No. The scroll-world workflow assembles a rendered video chain and scrubs playback as the visitor scrolls. Three.js renders a scene in the browser and can respond to camera or object input. Choose between them based on whether you need a directed story or interactive inspection, then test the loading and device costs.

Do these resources make a site discoverable by Google or LLMs?

They help implementation, not guaranteed discovery. Put the useful text and links in crawlable HTML, use descriptive titles and headings, expose the page through navigation and a sitemap, and keep the content available without animation. A machine-readable index can help agents navigate, but it does not guarantee indexing, ranking or citation.
