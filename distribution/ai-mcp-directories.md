# Where to submit AI tools, MCP servers and awesome lists

Choose a destination that accepts what you built. A product directory takes a website listing. An MCP registry needs a callable server or package. An awesome list has a narrower scope and a maintainer who decides what belongs.

Submission routes checked on 16 October 2026. Check the linked page again before paying or preparing a submission; intake and prices change.

## AI product directories

- [Toolify submission](https://www.toolify.ai/submit) has a paid listing form for AI tools. Review the current price and terms on that page before submitting. Its advertising and guest-post offers are separate products.
- [aitools.fyi](https://aitools.fyi) lists AI tools by category. Its Submit link currently opens [Boost My Tool](https://boostmytool.com), a paid directory-submission service. Check which destinations the service includes before buying it.

Neither listing establishes how much relevant traffic your product will receive. If budget is limited, start with the registry or curated list that matches your tool and measure visits before buying placements.

## MCP registries

- [Official MCP Registry publishing guide](https://modelcontextprotocol.io/registry/quickstart): publish metadata with `mcp-publisher` and verify your namespace. Package servers and remote-only servers have different setup steps; follow the section for your transport. The registry stores metadata rather than hosting your server.
- [Smithery publishing guide](https://smithery.ai/docs/build/publish): publish a public HTTPS server through [smithery.ai/new](https://smithery.ai/new), or distribute a local server as an MCPB bundle. The guide explains Streamable HTTP, OAuth, scanning and the metadata fallback when a scan cannot complete.
- [Glama MCP directory](https://glama.ai/mcp/servers): use Add Server in the directory and follow the requirements for your server type. Keep authentication and installation details available in your own repository or docs so readers can assess the listing.

Prepare the server name, a working setup guide, transport, authentication method, repository or package URL, and any usage costs. Check each registry's schema; they do not all ask for identical metadata.

## Curated lists and list trackers

- [Awesome MCP Servers contribution rules](https://github.com/punkpeye/awesome-mcp-servers/blob/main/CONTRIBUTING.md): accepts servers with a public GitHub repository that users can install and run. Read its scope before opening a PR, especially for a hosted-only server. Match the category, format and alphabetical order.
- [Awesome Claude Code contribution rules](https://github.com/hesreallyhim/awesome-claude-code/blob/main/CONTRIBUTING.md): recommendations use its web issue form. The maintainer requires humans to submit recommendations and currently asks for a project at least 14 days old with continued development, or at least 100 stars. Check the current rules before submitting.
- [Track Awesome List](https://www.trackawesomelist.com/#contribution): request tracking by editing [config.yml](https://github.com/trackawesomelist/trackawesomelist-source/blob/main/config.yml) in a PR, or opening an issue in the source repository. Inclusion requires a request; it is not automatic.
- [Sindre Sorhus's Awesome index](https://github.com/sindresorhus/awesome): the repository currently says pull requests are temporarily disabled. Recheck its banner and [contribution rules](https://github.com/sindresorhus/awesome/blob/main/contributing.md) before preparing an application.

## Before submitting

Check for an existing listing or open submission. Give the maintainer one factual sentence, a working link, setup instructions and an accurate explanation of free access, trials and paid requirements. Disclose your affiliation with the project.

For a tool submission, include an example someone can reproduce. For an awesome list, make sure readers can navigate the categories and reach the linked resources. After publication, compare referral visits and new stars with your previous baseline; a merged submission alone does not measure readership.
